# ADR-109 — Represent scenarios as sparse temporal graph overlays

> **Status:** Proposed reference specification  
> **Project:** GOLEM — Go Open Lifecycle & Engineering Manager  
> **Baseline reviewed:** `main` around commit `113c868…` (2026-08-19)  
> **Goal:** evolve GOLEM into an **Active Engineering Graph** / auditable engineering digital twin.  

## Status
**Proposed**

## Context
Full graph copies are expensive, while simulations need isolation and deterministic comparison to a known base.

## Decision
Scenario = base journal position + sparse overlay mutations + assumptions + results. Scenario graph queries compose base state with overlay.

## Consequences
Efficient forks and diff. Query layer becomes more complex and some engines may need materialized temporary snapshots.

## Alternatives considered
Clone database per scenario; model scenarios only as documents without graph semantics.
