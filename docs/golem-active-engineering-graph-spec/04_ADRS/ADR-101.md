# ADR-101 — Make command idempotency atomic with journal append

> **Status:** Proposed reference specification  
> **Project:** GOLEM — Go Open Lifecycle & Engineering Manager  
> **Baseline reviewed:** `main` around commit `113c868…` (2026-08-19)  
> **Goal:** evolve GOLEM into an **Active Engineering Graph** / auditable engineering digital twin.  

## Status
**Proposed**

## Context
Command events and command receipt currently risk a crash window when persisted through different authority paths.

## Decision
The journal adapter contract will support an atomic command append invariant containing command-ID uniqueness, accepted events and receipt. Receipt registry becomes derived/cache where practical.

## Consequences
Closes duplicate-write window and clarifies source of truth. Some adapters need transactional capability or a fallback protocol.

## Alternatives considered
Best-effort registry save; distributed transaction with separate databases; rely on clients not retrying.
