# ADR-062 — Tool Port and Capability Catalog v2

**Status:** Accepted
**Date:** 2026-08-18

## Context

M7 introduces agents that invoke tools to perform actions. The tool port
must provide:

1. A closed permission catalog (no dynamic permissions).
2. Journaled invocations for auditability.
3. Clear interface for tool implementations.

## Decision

1. **Permission catalog (closed, v2)**:
   ```go
   const (
       PermissionRead    = "read"
       PermissionWrite   = "write"
       PermissionDelete  = "delete"
       PermissionExecute = "execute"
       PermissionAdmin   = "admin"
   )
   ```
   Only these 5 permissions exist. No dynamic permission creation.

2. **Tool port** (`internal/ports/tools.go`):
   ```go
   type Tool interface {
       Invoke(ctx context.Context, input ToolInput) (ToolOutput, error)
       Spec() ToolSpec
   }
   ```

3. **ToolSpec** describes the tool interface:
   ```go
   type ToolSpec struct {
       Name        string
       Permissions []string // subset of permission catalog
       Description string
       InputSchema ToolInputSchema
   }
   ```

4. **ToolInput/ToolOutput** for journaled invocations:
   - Input: `TenantID`, `ToolName`, `Params`.
   - Output: `TenantID`, `ToolName`, `Result`, `Error`, `Success`.

5. **Errors**:
   - `ErrUnknownPermission` — permission not in catalog.
   - `ErrToolInvokeFailed` — invocation failed.

## Consequences

- Agents can only use tools with permissions from the closed catalog.
- All tool invocations are journaled via ToolInput/ToolOutput.
- No runtime permission escalation possible.
- Extending permissions requires an ADR (closed catalog principle).

## Alternatives considered

- **Dynamic permissions**: rejected — creates security surface without clear benefit;
  auditability is better served by a closed catalog.
- **Streaming tool results**: rejected for v1 — synchronous invocation is simpler
  and sufficient for offline eval harness.
