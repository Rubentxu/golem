# ADR-061 — LLM Provider Port and Capabilities

**Status:** Accepted
**Date:** 2026-08-18

## Context

M7 introduces LLMs and agents into the authority plane of GOLEM. Before
any agentic behavior can execute, GOLEM needs a stable port interface for
LLM providers. The port must:

1. Be deterministic for reproducible evaluation (eval harness).
2. Support capability declaration (retention, region, audit).
3. Not leak vendor DTOs (OpenAI.ChatCompletion, etc.) into internal/.
4. NOT support streaming — completions are returned as a whole.

## Decision

1. **LLMProvider port** (`internal/ports/llm.go`):
   ```go
   type LLMProvider interface {
       Complete(ctx context.Context, req LLMRequest) (LLMResponse, error)
       Capabilities() LLMProviderCapabilities
   }
   ```
   - `Complete` returns the full completion (no streaming).
   - `Capabilities` reports provider properties.

2. **LLMProviderCapabilities**:
   ```go
   type LLMProviderCapabilities struct {
       NoRetention bool   // provider does not store prompts/responses
       Region      string // deployment region or "local"
       Audit       bool   // provider emits audit events
   }
   ```

3. **LLMRequest/LLMResponse** are port types (not vendor DTOs):
   - Request: `TenantID`, `Prompt`, `Model` (optional).
   - Response: `TenantID`, `Content`, `Model`, `Provider`, `TokenUsed`.

4. **EmbeddingProvider port** for vector embeddings:
   ```go
   type EmbeddingProvider interface {
       Embeddings(ctx context.Context, req EmbeddingRequest) (EmbeddingResponse, error)
   }
   ```

5. **Sentinel errors**:
   - `ErrInvalidLLMRequest` — malformed request.
   - `ErrProviderUnavailable` — provider unreachable.
   - `ErrProviderCapability` — capability not supported.

## Consequences

- Agentic behaviors can use any LLM provider via the port.
- Deterministic replay is guaranteed when using deterministic providers (memstore).
- Vendor SDKs (sashabaranov/go-openai, anthropic-sdk-go, etc.) stay in adapters/.
- Streaming is intentionally not supported; agents receive complete responses.

## Alternatives considered

- **Streaming support**: rejected for v1 — adds complexity without clear benefit
  for offline eval harness; can be added behind a capability flag in v2.
- **Vendor DTOs in port**: rejected — vendor types must not cross adapter boundaries
  (ADR-045/ADR-047).
