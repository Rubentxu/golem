# ADR-076: Per-Tenant Quotas

**Status**: Accepted

**Date**: 2026-08-18

## Context

M8 introduces per-tenant quota enforcement to prevent any single tenant from
consuming disproportionate resources. This ADR describes the quota model and
enforcement strategy.

## Decision

We will implement per-tenant quotas with the following characteristics:

1. **Quota Model**: Each tenant has a quota defining limits on:
   - Events per window (e.g., 10,000 events/hour)
   - Storage in bytes
   - Operations per minute

2. **Enforcement Modes**:
   - `audit`: Log violations but do not block
   - `hard`: Block operations that would exceed quota
   - `adaptive`: Gradually throttle when approaching quota

3. **Quota Window**: Rolling window (default 1 hour) with automatic reset.

4. **Grace Period**: 5-minute grace period before enforcing hard limits.

5. **TenantCatalog Integration**: Quotas are stored in the TenantCatalog and
   fetched on each tenant operation.

## Consequences

- **Positive**: Prevents noisy-neighbor problem.
- **Positive**: Configurable enforcement allows gradual rollout.
- **Negative**: Requires TenantCatalog availability for every operation.
- **Negative**: Adaptive mode adds latency complexity.
