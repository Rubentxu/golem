# ADR-067 — AgentEval as First-Class Graph Node and AgentChangeLens

**Status:** Accepted
**Date:** 2026-08-18

## Context

M7 introduces agent evaluation into GOLEM. When an agent runs, it produces an
`agent.eval.completed.v1` event with the evaluation outcome, cost, and rationale.
This event must be:

1. Projectable into the Engineering Graph as a queryable node.
2. Traversable via lens queries (e.g., "what behavior changes did this agent propose?").
3. Correlatable with the Behavior being evaluated and the Proposal that triggered it.

This ADR defines AgentEval as a first-class canonical graph node kind and
establishes the AgentChangeLens family.

## Decision

### 1. AgentEval Canonical Node

`AgentEval` is a canonical node kind in the ontology schema (`kind_enum`).
It represents a single evaluation run of an agent Behavior.

**Attributes:**

| Key | Type | Description |
|---|---|---|
| `eval_id` | string | Unique evaluation ID |
| `behavior_id` | string | Behavior being evaluated |
| `tenant_id` | string | Tenant scope |
| `run_seq` | uint64 | Run sequence number within the behavior |
| `outcome` | string | "pass", "fail", "error" |
| `cost_usd` | float64 | Evaluated cost in USD |
| `latency_ms` | uint64 | Wall clock latency in ms |
| `policy_violations` | int | Number of policy violations |
| `proposal_id` | string | Proposal that triggered this eval (optional) |

### 2. Canonical Edges

Two canonical edge types link AgentEval nodes:

- **`EVALUATED`**: AgentEval → Behavior. The agent evaluated this Behavior.
- **`OBSERVED`**: AgentEval → Proposal. The agent's proposal is tracked by this eval.

### 3. AgentChangeLens

The `AgentChangeLens(roots, depth, maxNodes, maxEdges)` lens family returns the
subgraph reachable from AgentEval roots via `EVALUATED` and `OBSERVED` edges:

```
AgentEval → EVALUATED → Behavior
AgentEval → OBSERVED  → Proposal
```

Tenant isolation: all traversals are scoped to one `TenantID`.

### 4. Projector

The `AgentEvalProjector` (`internal/canonical/agent_eval_projector.go`) applies
`agent.eval.completed.v1` journal events to the graph:

- ID derivation: `sha256(behavior_id + tenant_id + run_seq)[:8]`
- Idempotent: same event twice → no duplicate node
- Fails closed: if the referenced Behavior or Proposal does not exist, the
  projection returns an error without a partial graph (ESC-032).

### 5. Canonical Export Extension

`Manifest.Extensions["agent_evals"]` contains all AgentEval nodes in the canonical
export archive (alongside `nodes.jsonl`/`edges.jsonl`). This enables
round-trip export → import → query including agent evaluations.

## Consequences

### Positive

- Agent evaluations are first-class graph citizens — queryable via lens.
- AgentChangeLens enables "what did this agent change?" queries.
- Idempotent projector ensures replay safety.
- Fail-closed projector prevents partial graph pollution.

### Negative

- AgentEval nodes increase graph size — consider TTL/archival for old evals.
- The `sha256` ID derivation is not user-friendly for debugging.
