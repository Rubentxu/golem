# ADR-057 — Provider Profile and Adapter Selection

**Status:** Accepted
**Date:** 2026-08-18

## Context

GOLEM's M5 milestone closes the exit criterion "second implementation/simulator for critical ports and R4 migration rehearsal". The composition root today hardcodes all adapters in `cmd/golem-api/main.go:32-53` and `cmd/golem-worker/main.go:30-45`. The hardcode has an explicit TODO ("provider profiles arrive with M5"). To run the same kernel against different storage backends (bbolt journal, NATS transport, future HugeGraph) without recompiling, the composition root must select adapters from a configuration artefact — without becoming a service locator in `internal/`.

## Decision

1. **Profile = YAML file resolved by env var**. `GOLEM_PROFILE` selects `golem-profile.{name}.yaml`. Resolution order: `./`, `$GOLEM_PROFILE_DIR/`, `/etc/golem/`. Default `dev`. Parse via stdlib `encoding/json` (YAML 1.2 ⊃ JSON); the file is JSON-shaped (no comments, no anchors).

2. **Profile shape**:
   ```yaml
   version: 1
   name: dev | durable
   adapters:
     journal:   memstore | bbolt
     graph:     memstore
     registry:  memstore
     transport: memstore | natsjs
     checkpoint: memstore
     search:    memstore
   options:                            # adapter-specific knobs
     bbolt: { path: "./var/golem.journal", file_mode: "0600" }
     natsjs: { url: "${env:GOLEM_TEST_NATS_URL}", stream: "golem" }
   ```

3. **Selection happens at bootstrap, never at runtime**. The loader lives in `internal/profile/` and is imported only by `cmd/golem-api/main.go` and `cmd/golem-worker/main.go`. `internal/domain/` and `internal/application/` never see `Profile{}` — they receive `runtime.Options` already constructed. Archtest asserts this: any new import of `internal/profile` outside `cmd/` is a violation.

4. **`durable` fallback policy**. When NATS is unreachable (`GOLEM_TEST_NATS_URL` empty or connect fails), the `durable` profile logs `WARN transport=natsjs unavailable; falling back to memstore transport` and continues. Fail-fast is rejected: dev/CI environments should not block on optional infrastructure.

5. **Profile failure is fail-fast with log line**. `Load` returns `(Profile, error)`; `cmd/main.go` logs the resolved path + name and `log.Fatalf` on error. No silent fallback to `dev` (that hides bugs).

6. **bbolt exception documented**. `go.etcd.io/bbolt` is the only third-party import in `internal/`-adjacent code, used exclusively inside `adapters/journal/bbolt/`. Archtest deny-list extends with `"go.etcd.io"`. The vuln **GO-2026-4923** was withdrawn by the bbolt maintainers; pin `v1.5.0` exactly.

7. **Future-proofing**. M5.1 will add `durable-postgres`, `oci-registry`, `wazero-host`. Adding a profile = adding a yaml file + a factory function in `internal/profile/`. No new ports are required.

## Rationale

The composition root has one job: wire ports to adapters. Today it does so by hardcoded imports; M5 replaces the imports with a lookup from `runtime.Options` populated by `profile.Load`. The discipline that prevents this becoming a service locator is the import boundary (archtest) and the placement rule (selection at bootstrap only). The "JSON-shaped YAML" compromise trades ergonomics (no comments) for purity (no new vendor dep in `internal/`).

## Consequences

### Positivas

- Profile = deployable artefact: `dev`, `staging`, `prod`, `chaos` are files, not code.
- Composition root is now ~20 lines of `runtime.New` calls — readable.
- ADR-045 + ADR-047 preserved by archtest + import boundary.
- bbolt adapter passes TCK → SP-002 (journal persistence) closed.
- Profile loader is unit-testable independently of the kernel.

### Trade-offs

- No comments in profile YAML — operators edit structured fields only.
- `durable` profile degrades gracefully (warning, not fail-fast) — production must use IaC checks, not assume degradation is impossible.
- `go.etcd.io/bbolt` is one new third-party dep — documented and pinned; archtest enforces isolation.
- `internal/profile/` is a 4th "internal-only" package — but its imports are restricted to stdlib, so it remains test-friendly.

### Alternatives considered

- **`gopkg.in/yaml.v3`** for true YAML support — rejected (vendor in `internal/` violates ADR-045).
- **Profile as Go struct** — rejected (kills "deployable artefact"; requires recompile per env).
- **Fail-fast on NATS unavailable** — rejected (degrades dev/CI; users run durable locally).
- **Profile loader in `cmd/` only (no shared pkg)** — rejected (code duplication between `golem-api` and `golem-worker`).
- **`internal/profile` is a port** — rejected (loader is bootstrap, not a swappable seam; the swappable seam is the adapter behind the port).

### Validation / fitness

- `tck.RunJournalStoreTCK` green against `adapters/journal/bbolt` in `just check`.
- `GOLEM_PROFILE` unset → `dev` profile → behavior bit-identical to M4 (all existing tests pass).
- `GOLEM_PROFILE=durable` boots bbolt journal; warning logged when NATS unavailable.
- `internal/archtest/imports_test.go` red if any new import of `internal/profile` from `internal/domain/` or `internal/application/`.
- `tck/migration_rehearsal_test.go` E2E green (happy path + rollback).
- Manifest `sha256` determinista; round-trip Export → Reader succeeds.
