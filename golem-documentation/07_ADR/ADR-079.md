# ADR-079: Metering Pipeline

**Status**: Accepted

**Date**: 2026-08-18

## Context

M8 introduces a metering pipeline to process metering events and produce daily rollups
exported to S3. This ADR describes the pipeline architecture.

## Decision

We will implement the metering pipeline with the following characteristics:

1. **Event Flow**:
   - Metering events are emitted by the metering hook on each capability invocation
   - Events flow through the journal to the metering aggregator
   - Hourly rollups are computed and stored
   - Daily rollups are exported to S3

2. **S3 Sink**:
   - Daily rollups exported to `s3://{bucket}/metering/{tenant}/{date}.json`
   - Rollup includes SHA256 digest for integrity verification
   - IAM role assumed for S3 access

3. **Dead Letter Queue (DLQ)**:
   - Failed events sent to DLQ topic `metering.dlq`
   - DLQ events can be replayed after fixing the issue
   - DLQ metrics exported to observability

4. **Hourly Rollup Job**:
   - Cron job runs at the end of each hour
   - Aggregates metering events by tenant and capability
   - Computes SHA256 digest for integrity

## Consequences

- **Positive**: Accurate billing via per-tenant metering.
- **Positive**: Audit trail via S3 rollups.
- **Negative**: S3 bucket and IAM configuration required.
- **Negative**: DLQ adds operational complexity.
