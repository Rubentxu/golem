# ADR-084 — Eliminar el journal postgres adapter

**Status:** Accepted
**Date:** 2026-08-19

## Context

Durante la revisión del estado del proyecto se identificó que `adapters/journal/postgres/` existe sin justificación en ningún ADR. El adapter fue añadido ad-hoc durante el ciclo M5 (commit `d2339c3`) fuera del proceso SDD, sin proposal ni design formales.

## Decision

Eliminar `adapters/journal/postgres/` completamente del repositorio.

## Rationale

1. **No hay ADR que lo justifique.** ADR-057 (Provider Profiles) muestra `journal: bbolt` como el adapter durable. ADR-005 y ADR-030 reconocen el journal como Graph Journal — no especifican ninguna tecnología.

2. **M5 proposal no lo incluye.** El proposal de M5-extensibility (CYC-2026-08-18) solo menciona `bbolt` como segundo journal adapter. El adapter postgres nunca fue parte del SDD workflow formal.

3. **No hay justificación de negocio.** El único uso real del adapter es el TCK `RunJournalStoreTCK`, que ya pasa contra `bbolt`. No hay producto, operación ni migración que requiera postgres como adapter de journal.

4. **Infra inconsistency.** El equipo creó infra podman con postgres para tests del journal, pero esto contradice la dirección de ADR-012 (NATS como reference transport) y ADR-057 (journal = bbolt en prod). Mantener postgres crea deuda deinfra innecesaria.

5. **Decisión de arquitectura no atravesó el proceso.** Añadir un adapter de persistencia sin ADR es exactamente el anti-patrón que ADR-046 y ADR-052 previenen.

## Consequences

### Positivas
- Eliminación de deuda deinfra: no hay reason para mantener postgres en el setup de desarrollo
- El proceso SDD se refuerza: cualquier adapter nuevo requiere proposal + design + ADR
- TCK sigue verde contra `bbolt`

### Negativas
- Cualquier test de integración que use postgres journal no puede ejecutarse
- Si en el futuro se necesita migración bbolt→postgres, el adapter se reconstruye desde cero (costo conocido, aceptable)

### Trade-offs
- Se pierde la posibilidad de tests de integración con postgres real (bbolt con tmp dir es suficiente para tests de regresión)

## Alternatives considered

| Alternative | Rejected because |
|-------------|------------------|
| Mantenerlo como "alternativa" | No hay ADR que justifique su existencia; el TCK de postgres no tiene caso de uso real |
| Renombrarlo a "benchmark adapter" | El benchmark gate usa contenedores ephemeral, no un adapter permanente en el repo |

## Validation / fitness

- `just check` verde sin postgres
- `adapters/journal/postgres/` eliminado del filesystem
- `go mod tidy` retira `github.com/jackc/pgx/v5` si no tiene otros usos
- Todo profile usa `journal: bbolt` o `journal: memstore` exclusivamente
