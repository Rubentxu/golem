# ADR-056 — Typed graph traversal with explicit truncation

**Status:** Accepted
**Date:** 2026-08-17

## Context

GOLEM necesita traversals de grafo con filtro por tipo de arista y por kind de nodo para soportar blast radius y la gate v2 sobre supply-chain. El método existente `GraphStore.Neighborhood` realiza un BFS no-tipado, sin filtros de arista ni de kind, y trunca en silencio cuando se alcanza `MaxNodes`/`MaxEdges` — el resultado parece completo pero no lo es, lo que para blast radius es peor que un error explícito. Sin un mecanismo de truncación visible, callers como blast radius pueden devolver respuestas parcialmente correctas y dar falsa confianza al operador.

## Decision

El puerto `GraphStore` se extiende aditivamente con un método `Traversal(ctx, TraversalQuery) → Subgraph`:

```text
TraversalQuery { TenantID, Roots [], EdgeTypes [], Kinds [], MaxDepth, MaxNodes, MaxEdges }
Subgraph { Nodes [], Edges [], Truncated bool }
```

- `EdgeTypes` y `Kinds` vacíos significan "cualquiera" (compatibilidad con `Neighborhood`).
- `Subgraph.Truncated` se setea a `true` cuando se alcanza cualquier bound (`MaxDepth`, `MaxNodes` o `MaxEdges`) antes de completar el walk.
- `Neighborhood` permanece intacto para callers que no necesitan tipado.

Los callers internos que requieren walks tipados (blast radius, gate v2 walk) migran de `Neighborhood` a `Traversal`. `Neighborhood` queda **deprecated for internal use where typed walks exist**; los callers externos que hoy usan `Neighborhood` para vistas no-tipadas siguen funcionando. La TCK `RunGraphStoreTCK` extiende con tres casos: typed walk honoring edge-type filter, truncation flag set cuando un bound se alcanza, cross-tenant typed walk returns empty. La impl de referencia en `adapters/graph/memstore` implementa `Traversal` reusando el loop BFS de `Neighborhood` y añadiendo filtro de arista y kind en el frontier; el flag `Truncated` se setea dentro del `break loop` cuando se viola `MaxNodes`/`MaxEdges`.

## Rationale

Cambio aditivo del puerto preserva contratos existentes (ADR-021 optimistic concurrency, ADR-046 cada puerto crítico con TCK). Blast radius necesita aristas específicas (`CONTAINS`, `HAS_SBOM`, `RELEASED_AS`) y kinds específicos (`PackageComponent`, `SBOM`, `Artifact`, `Release`) — un walk no-tipado atraviesa el grafo entero y viola `MaxNodes` antes de llegar al destino. La flag `Truncated` convierte "truncación silenciosa" en "truncación observable": el caller decide si continuar (más queries) o fallar. Mantener `Neighborhood` evita churn en callers que no requieren tipado (visualización de grafo, queries ad-hoc) y respeta el principio de "evolución aditiva antes que mutación". El deprecation-for-internal-use es política, no syntactic sugar: un lint o grep en CI puede detectar callers que migran.

## Consequences

### Positivas

- Decisión explícita y verificable: el TCK cubre typed walk + truncation + cross-tenant typed walk.
- Reduce acoplamiento entre callers y topología del grafo: blast radius declara los edge types que necesita y el walk respeta ese filtro.
- Truncation visible elimina el peor escenario (resultado parcial tomado como completo); los callers deben decidir antes de presentar el resultado al usuario.
- Compatibilidad aditiva: ningún caller existente de `Neighborhood` se rompe.
- Migración interna gradual: blast radius y gate v2 migran primero; el resto queda con `Neighborhood` hasta evidenciar necesidad de tipado.

### Trade-offs

- Dos métodos en el puerto (`Neighborhood` + `Traversal`) aumentan la superficie; mitigación: documentar `Neighborhood` como legacy para vistas y forzar `Traversal` en callers tipados.
- El flag `Truncated` introduce una decisión adicional para cada caller: reintentar con bounds más amplios, fallar, o devolver parcial. Sin guía explícita, callers divergen. Mitigación: documentar el contrato en el doc-comment del puerto y exigir el escenario en el TCK.
- `EdgeTypes` y `Kinds` vacíos = "cualquiera" pueden confundir: un caller que olvida pasar filtros obtiene BFS no-tipado. Mitigación: el doc-comment deja explícito que la omisión es intencional y se alinea con `Neighborhood`.
- Reusar el loop BFS de `Neighborhood` con filtros introduce una rama extra en hot path; el loop ya era O(V+E) y el filtro es O(1) por arista/nodo, así que el impacto es marginal.
- Deprecation-for-internal-use es política sin enforcement automático; un lint o grep en CI lo aplica, pero hay que mantenerlo.

## Alternatives considered

- **Modificar `Neighborhood` in-place para añadir filtros**: rejected — rompe contrato (callers existentes interpretan filtros de forma distinta), pierde backward compatibility (ADR-021) y dificulta el rollout.
- **Read-model separado (vistas materializadas)**: rejected — duplica material entre projection y read model, contradice ADR-049 (derived stores rebuildable pero no por evento) y complica invalidación ante projection rebuild.
- **Walk recursivo sin bounds**: rejected — contradice la regla "toda traversal es acotada" de GRAPH_MODEL y bloquea query safety.
- **Truncation como error (no como flag)**: rejected — fuerza retry o fallo en casos donde el caller puede trabajar con resultados parciales (visualización, blast radius con fallback). El flag es más flexible.
- **Single method `Walk` con opciones funcionales**: rejected — pierde claridad de contrato: el TCK necesita saber qué firma assertar y los callers necesitan saber qué parámetros pasan.

## Validation / fitness

- `RunGraphStoreTCK` extendido con tres nuevos casos:
  - `typed walk honors edge-type filter`: grafo con `DEPENDS_ON` + `IMPLEMENTS` desde `n1`; walk con `EdgeTypes=[IMPLEMENTS]` retorna solo `IMPLEMENTS`.
  - `truncation flag set when a bound is hit`: cadena de 100 con `MaxNodes=5`; `Subgraph.Truncated == true` y `len(Subgraph.Nodes) <= 5`.
  - `cross-tenant typed walk returns empty`: typed walk con `TenantID=t1` no retorna nodos de `t2`.
- `TestBlastRadiusTruncatedSurfaced` en `internal/application/supplychain/blast_test.go`: componente con >100 aristas linkeadas y `MaxNodes=10`; assert `Truncated=true` y `Releases` parcial.
- `TestGateV2HonorsTraversalBounds`: release con >100 componentes, walk tipado con `MaxEdges=10`; assert `Truncated` propagado al evento de gate.
- `TestNeighborhoodStillWorks`: caller existente sigue retornando resultados no-tipados sin cambios.
- `internal/archtest` confirma que ningún caller interno usa `Neighborhood` para walks tipados (grep sobre `adapters/` e `internal/application/`); el deprecation-for-internal-use queda visible en el comentario del puerto.
- Golden events y projection invariants preservados; replay determinista con `Traversal` idéntico para mismo input.
