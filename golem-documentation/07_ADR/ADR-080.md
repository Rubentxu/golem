# ADR-080: SLO Framework

**Status**: Accepted

**Date**: 2026-08-18

## Context

M8 introduces a formal SLO (Service Level Objective) framework to provide
quantifiable reliability guarantees for the GOLEM SaaS platform. This ADR
describes the SLO framework architecture covering 13 SLIs, error budget
policies, burn rate alerting, and the tracking infrastructure.

## Decision

We will implement the SLO framework with the following characteristics:

### 1. SLI Definitions (13 total)

| # | SLI Name | Metric | Target | Window |
|---|----------|--------|--------|--------|
| 1 | `command.latency.p99` | Command API p99 latency | < 250ms | 1h rolling |
| 2 | `command.error_rate` | Command API error rate | < 0.1% | 1h rolling |
| 3 | `system.availability` | System availability | ≥ 99.9% | 30d |
| 4 | `journal.replay_time.p99` | Journal replay p99 time | < 50ms | 1h rolling |
| 5 | `agent.eval_pass_rate` | Agent evaluation pass rate | ≥ 80% | 1h rolling |
| 6 | `oidc.verify_latency.p99` | OIDC token verify p99 latency | < 100ms | 1h rolling |
| 7 | `ops.console.action_latency.p99` | Ops console action p99 latency | < 500ms | 1h rolling |
| 8 | `audit.export.success_rate` | Audit export success rate | ≥ 99% | 1h rolling |
| 9 | `metering.rollup.success_rate` | Metering rollup success rate | ≥ 99.5% | 1h rolling |

Additional SLIs tracked internally:
- `quota.check_latency.p99` — Quota check p99 latency
- `cell.migrate.duration.p99` — Cell migration p99 duration
- `snapshot.duration.p99` — DR snapshot p99 duration
- `meter.query_latency.p99` — Metering query p99 latency

### 2. Error Budget Policy

Each SLO has an initial error budget derived from its target:

```
error_budget = (1 - target) × window_duration
```

Budget is consumed when SLIs are violated. Budget consumption rate is
tracked as the burn rate.

### 3. Burn Rate Alerting

Burn rate is computed as:

```
burn_rate = error_rate / allowed_error_rate
```

Alert thresholds:
- **2x burn rate** (window 1h): Emit `slo.budget.burn.v1` event, page on-call.
- **2x burn rate** (window 6h): Emit `slo.budget.burn.v1` event, escalate.
- **Budget exhausted >90%**: Emit `slo.budget.exhausted.v1` event.

### 4. SLOTracker Port

```go
type SLOTracker interface {
    Record(ctx context.Context, sloName string, value float64) error
    Evaluate(ctx context.Context) ([]SLOViolation, error)
}
```

Implementations: memstore (development), OTLP-backed (production).

### 5. Evaluation Loop

The SLO evaluator runs every 60 seconds, evaluating all registered SLOs
and emitting appropriate events and alerts.

## Consequences

- **Positive**: Quantifiable reliability targets for GA.
- **Positive**: Early warning via burn rate alerting.
- **Positive**: Standardized metrics across all platform components.
- **Negative**: Operational overhead of running the evaluator loop.
- **Negative**: Alert fatigue if thresholds not tuned properly.
