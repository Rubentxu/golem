# ADR-013 — Graph database choice requires benchmark gate

**Status:** Accepted  
**Date:** 2026-08-17 (Accepted 2026-08-19 tras ADR-087)

## Context

GOLEM debe operar como SaaS graph-native, event-driven y extensible, con una arquitectura evolutiva y provider-independent.

## Decision

Apache HugeGraph es candidato inicial; NebulaGraph y otras alternativas se compararán con workloads GOLEM.

## Rationale

La graph DB es una decisión costosa que debe basarse en benchmark, licencia y operación.

## Consequences

### Positivas
- La decisión queda explícita y verificable.
- Reduce acoplamientos implícitos.
- Facilita evolución y revisión por evidence.

### Trade-offs
- Requiere disciplina de contracts, tests y docs.
- Las optimizaciones vendor-specific deben quedar dentro del adapter.
- Puede añadir trabajo inicial para ahorrar migraciones costosas.

## Alternatives considered

Acoplamiento directo, abstracción posterior y decisiones ad-hoc. Se rechazan como baseline porque desplazan el coste a una fase más cara.

## Validation / fitness

La decisión se protege mediante architecture tests, contract/TCK tests, benchmarks o CI según corresponda.

## Resolution (post ADR-013)

El benchmark gate se completó el 2026-08-19 con la aceptación de **ADR-087 — Graph database elegida: Dgraph**. HugeGraph quedó descartado por incompatibilidad de edge kind enforcement con el modelo journal-first de GOLEM. NebulaGraph quedó diferido por complejidad operacional de 3 servicios, con triggers de re-evaluación documentados en ADR-087 (Monitoring plan).
