# ADR-070: Agentic Eval Harness — Offline Replay with Held-Out Fixtures

## Status
Accepted

## Date
2026-08-18

## Context

The agentic layer requires a deterministic, offline evaluation harness that:
1. Replays agent behavior from saved checkpoints (Given/When/Then/Completed/RolledBack steps)
2. Scores agent outputs using weighted metrics (cost, latency, policy violations)
3. Supports held-out fixture sets for cross-validation
4. Is isolated from live infrastructure (LLM provider, graph store)

This ADR defines the eval harness architecture.

## Decision

### Harness Model

The harness executes a `Fixture` through a deterministic `Step` enum:

```
Idle → Given → When → Then → Completed
                    ↘ RolledBack
```

- **Given**: Load checkpoint (frame, initial graph state)
- **When**: Execute agent with injected ports (LLM, Tools, Budget, Tracer, Journal, Redactor)
- **Then**: Compare output against `FixtureExpected`
- **Completed**: All steps finished normally
- **RolledBack**: Error or budget exceeded; rollback applied

### Fixture Structure

```go
type Fixture struct {
    ID      string
    Tenant  ports.TenantID
    Version int
    Input   FixtureInput
    Expected FixtureExpected
    Scoring FixtureScoring
}

type FixtureInput struct {
    ScenarioID          string
    Frame               ports.Frame
    CanonicalExportPath string  // path to checkpoint archive
}

type FixtureExpected struct {
    ProposalID              string
    RationaleContains       []string
    OperationsMinCount      int
    MustNotMutateGraphDirectly bool
    PolicyViolationCount    int
}

type FixtureScoring struct {
    PassFormula         string  // e.g. "rationale_matches AND operations_present AND policy_violations=0"
    CostWeight          float64
    LatencyWeight       float64
    PolicyViolationWeight float64
}
```

### Checkpoint Format

Checkpoints are stored as gzipped JSON archives at `canonical_export_path`:

```json
{
  "version": 1,
  "frame": { /* ports.Frame JSON */ },
  "graph": {
    "nodes": [ /* serialized nodes */ ],
    "edges": [ /* serialized edges */ ]
  },
  "journal": [ /* journal event IDs for replay */ ]
}
```

### Scoring Algorithm

```
Score = (cost_score * cost_weight +
         latency_score * latency_weight +
         policy_score * policy_violation_weight) / total_weight

where:
  cost_score = max(0, 1 - (actual_cost_usd / budget_usd))
  latency_score = max(0, 1 - (actual_latency_ms / budget_ms))
  policy_score = max(0, 1 - (policy_violations / max_violations))
```

Pass formula is evaluated as a boolean expression against rationale and operations.

### Fixture Sets

| Set | Path | Purpose |
|-----|------|---------|
| v1 | `internal/agent/harness/fixtures/cases/v1/` | Training / development |
| v1-held-out | `internal/agent/harness/fixtures/cases/v1-held-out/` | Held-out evaluation |

Held-out fixtures use different graph revisions, unknown CVE IDs, and PII-laden inputs to prevent train/test contamination.

### Observable Events (ADR-066)

The harness emits journal events for every step:

- `agent.eval.started.v1` — harness started
- `agent.eval.step.v1` — step transition (Given/When/Then/Completed/RolledBack)
- `agent.eval.scored.v1` — scoring result with breakdown
- `agent.eval.completed.v1` — all fixtures evaluated

All prompts and responses are pre-processed through `observability.Redactor` before journaling.

### Engine Wiring

Agentic behaviors use a dedicated engine constructor:

```go
func NewEngineWithAgentic(reg *Registry, graph ports.GraphStore, clock ports.Clock, opts EngineOptions) *Engine
```

The `EngineOptions` struct injects:
- `AgenticLLM` — LLM provider
- `AgenticTools` — available tools
- `AgenticFrame` — default frame
- `AgenticBudget` — budget limits
- `AgenticTracer` — OTel tracer (GenAI semconv v1.20.0)
- `AgenticJournal` — journal store
- `AgenticRedactor` — PII redaction

## Consequences

### Positive
- Fully offline, deterministic eval with no live infra dependency
- Checkpoint replay enables debugging agent behavior from any step
- Held-out fixtures provide honest cross-validation
- Weighted scoring balances cost, latency, and safety

### Negative
- Checkpoint serialization adds complexity
- Fixture authoring requires domain expertise

### Risks & Mitigations
- **Checkpoint drift**: Checkpoint format versioned; loader rejects mismatched versions
- **PII in fixtures**: `Redactor` applied before journaling; fixtures must not contain real PII
