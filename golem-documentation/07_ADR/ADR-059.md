# ADR-059 — Behavior Engine v1: Deterministic Native Behaviors

**Status:** Accepted
**Date:** 2026-08-18
**Supersedes:** ADR-037 (Graph Lenses bound execution context)

## Context

M6 (Reactive Graph & Scenarios) demands "Behaviors, Relation Behaviors,
Pattern DSL/compiler, Lenses, Frames, fork/diff/promote y shadow
behaviors" with exit "what-if reproducible y behavior v1/v2 diff". The
stub ADRs 037/040/044 declared these intentions without design. With the
typed Traversal substrate (M4) and the deterministic journal, the
behavior engine can be built now — but WASM handlers (ADR-044's real
concern) have no non-native consumer until external behaviors exist.

## Decision

1. **Behaviors are journal-driven pure functions.** Model: `id, version,
   subscriptions, filters, lens_spec, execution_policy, budget, handler`
   (BEHAVIOR_RUNTIME.md §Behavior). Two versions of the same ID coexist
   in the registry — shadow executions need both.
2. **Handlers are native Go in v1** (`internal/behavior`). The handler
   receives the triggering event, the materialised lens result, and
   injected Clock/IDs. External I/O only via Tool ports (v1: none).
   WASM handlers arrive in M6.1 with the first non-native behavior —
   the host-function catalogue for them is already the M5.1 permission
   set (ADR-058).
3. **The pipeline is BEHAVIOR_RUNTIME.md §Activation**: Accepted Event →
   subscription index → cheap predicates → candidate set → graph pattern
   (lens over TraversalQuery) → handler → events/proposals. Failures are
   observable outcomes (skipped, budget exceeded); broken invariants and
   invalid inputs are errors (§Failure model).
4. **Determinism by construction.** Output event IDs derive from
   `sha256(event_id:seq)` per run — re-executing the same event produces
   byte-identical outcomes. Injected ULID generators would break replay
   reproducibility, so the engine derives IDs itself.
5. **Lens spec IS the graph pattern** (ADR-037 realised): read-only,
   tenant-bound, budgeted by the TraversalQuery bounds; `Truncated` maps
   to `ErrLensBudgetExceeded` (fail-closed, no partial results).
   Serialisation is deterministic (sorted IDs, map-key sorted JSON).
   v1 families: VulnerabilityImpactLens and ReleaseEvidenceLens.
6. **Relation behaviors** derive traversal roots from the event payload
   (edge-keyed coordination) and skip when roots resolve empty.

## Consequences

- The exit criterion's "behavior v1/v2 diff" is demonstrable: shadow
  runs both versions sequentially over the same events and diffs
  semantic outcomes (outputs + skip reasons — never version identity).
- The DSL/compiler (M6.1) compiles patterns INTO LensSpec — the AST
  target already exists.
- Frames (ADR-040) remain future work: v1 execution policy+budget
  covers the bounded-context need without a separate frame concept.

## Alternatives considered

- **WASM handler in M6.0**: rejected — no non-native behavior exists;
  speculative host-function design (consistent with the M5.1 YAGNI).
- **Port for the behavior registry**: rejected — single in-memory
  provider; the port is born with the second adapter (ObjectStore
  pattern).
- **ULID-based output IDs**: rejected — breaks what-if reproducibility.
