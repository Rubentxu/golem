# ADR-081: Ops Console Operator-Only

**Status**: Accepted

**Date**: 2026-08-18

## Context

M8 introduces an operations console API for platform operators to perform
administrative actions: draining cells, migrating tenants, viewing SLO status,
and querying metering data. This ADR describes the operator-only access control
model, the API endpoints, audit logging, and RBAC requirements.

## Decision

We will implement the ops console with the following characteristics:

### 1. API Endpoints

| Method | Path | Description | Auth |
|--------|------|-------------|------|
| GET | `/readyz` | Deep readiness check | public |
| GET | `/status` | System status | operator |
| POST | `/admin/cells/{id}/drain` | Drain a cell | operator |
| POST | `/admin/cells/{id}/migrate?dryRun=true` | Tenant migration dry-run | operator |
| POST | `/admin/tenants/{id}/cell` | Assign tenant to cell | operator |
| GET | `/admin/slo/{sli}` | SLO status | operator |
| GET | `/admin/metering` | Metering data | operator |

### 2. Authentication & Authorization

- **Authentication**: OIDC bearer token (via ADR-082)
- **Authorization**: RBAC with `operator` role
- Operators must have the `golem.operator` capability in their JWT claims
- The `X-Golem-Actor-Id` header is replaced by OIDC principal

### 3. Audit Logging

Every administrative action emits an `ops.console.action.completed.v1` or
`ops.console.action.rejected.v1` event with:

- Actor (from OIDC token)
- Action performed
- Target resource
- Timestamp
- Outcome (success/failure)

### 4. RBAC Model

```go
role Operator {
  can: [cell:drain, cell:migrate, tenant:assign, slo:read, metering:read]
}
```

### 5. OpsConsole Port

```go
type OpsConsole interface {
    DrainCell(ctx context.Context, cellID CellID) error
    MigrateTenant(ctx context.Context, tenantID TenantID, dryRun bool) (*MigrationPlan, error)
    AssignTenantCell(ctx context.Context, tenantID TenantID, cellID CellID) error
    GetSLOStatus(ctx context.Context, sliName string) (SLOStatus, error)
    GetMeteringData(ctx context.Context) (*MeteringData, error)
}
```

## Consequences

- **Positive**: Operator actions are auditable and traceable.
- **Positive**: RBAC provides fine-grained access control.
- **Positive**: Separation of operator and user APIs.
- **Negative**: OIDC dependency for authentication.
- **Negative**: Added latency for audit logging.
