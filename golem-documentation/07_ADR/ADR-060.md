# ADR-060 — Scenarios: Fork / Diff / Promote over Overlay Deltas

**Status:** Accepted
**Date:** 2026-08-18
**Supersedes:** ADR-041 (Scenario fork/diff/promote is first-class)

## Context

M6's exit criterion first half is "what-if reproducible": evaluating a
hypothetical change (CVE, policy, behavior version) against the real
graph without mutating it, and promoting the accepted delta atomically.
The stub ADR-041 declared the intention; M5 delivered the two reusable
substrates (canonical export + the migration harness's replay and
semantic diff).

## Decision

1. **A scenario is a base journal position plus an overlay event delta**
   (SCENARIOS_FORK_DIFF_PROMOTE.md §Scenario). The full graph is never
   copied as a scenario artifact — the fork materialises in a caller-wired
   graph store (memstore in v1; file-backed arrives in M6.1 behind the
   ScenarioStore port).
2. **Fork = snapshot copy + overlay projection.** The snapshot copies
   nodes/edges via ListNodes/ListEdges; overlay events are projected with
   the SAME pipeline as the migration harness replay
   (`projection.ApplyIfHandled`) — graceful skip for events the projector
   does not handle. Overlay events never touch the real journal.
3. **Diff is structural and deterministic**: added/removed/changed nodes
   and edges, sorted by ID; affected releases classified (Release nodes
   touched); policy decisions reserved (v1 placeholder).
4. **Promote is atomic and lineage-checked.** Verify `base_position ≤
   journal head` (forking from the future is a conflict) → approval gate
   → ONE journal.Append with the overlay batch → `scenario.delta.promoted.v1`
   on stream `scenario.{id}` with lineage payload. No semantic auto-merge
   — the delta applies as-is (§Promote of the doc).
5. **Shadow behaviors are the v1/v2 diff mechanism**: sequential
   deterministic execution of two behavior versions over the same events
   with the same lens, comparing semantic outcomes only.

## Consequences

- "What-if reproducible" is guaranteed structurally: deterministic IDs,
  ordered outputs, sorted diffs — two forks over the same base and
  overlay are byte-identical.
- The scenario store port keeps the file-backed upgrade localised.
- Promoted events carry their lineage (scenario id, base position) in
  the promoting batch context — auditability without a graph node.

## Alternatives considered

- **Copy-on-write graph snapshots**: rejected for v1 — memstore copy via
  List/List is simple, bounded by corpus size; COW belongs to the
  production graph provider (M8).
- **Promote via individual appends**: rejected — breaks atomicity; a
  partial promotion would leave an unverifiable half-state.
- **Semantic auto-merge**: rejected explicitly by the governing doc.
