# ADR-077: SLO Enforcement Modes

**Status**: Accepted

**Date**: 2026-08-18

## Context

M8 introduces SLO tracking with configurable enforcement modes. This ADR describes the
SLO enforcement strategy and modes.

## Decision

We will implement SLO enforcement with the following modes:

1. **SLO Modes**:
   - `disabled`: No SLO tracking, no enforcement.
   - `audit`: Track SLO but do not enforce, log violations.
   - `soft`: Track SLO, emit warnings but allow operations.
   - `hard`: Block operations that would violate SLO.

2. **SLO Types**:
   - `availability`: Target uptime percentage (e.g., 99.9%)
   - `latency`: P95/P99 response time targets
   - `throughput`: Minimum transactions per second

3. **SLO Window**: Rolling window (default 30 days) for SLO calculation.

4. **Error Budget**: Deficit between actual and target is the error budget burn.

## Consequences

- **Positive**: Gradual rollout via mode selection.
- **Positive**: Clear separation between tracking and enforcement.
- **Negative**: SLO calculations add latency overhead.
- **Negative**: Error budget tracking requires persistent storage.
