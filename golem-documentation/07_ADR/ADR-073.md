# ADR-073: Security Agent — SBOM/VEX Vulnerability Fix Proposal

## Status
Accepted

## Date
2026-08-18

## Context

The agentic layer requires automated analysis of SBOM vulnerabilities and proposal of VEX (Vulnerability Exploitability eXchange) fixes. The Security agent:
1. Subscribes to `vulnerability.detected.v1` events
2. Uses `VulnerabilityImpactLens` to find blast radius (affected components → SBOM → artifacts → releases)
3. Calls LLM to reason about VEX "fixed" proposals
4. Outputs `Proposal{Operations:[CreateNode{VEXStatement}, AddEdge{MITIGATED_BY}]}` through the proposal lifecycle

This ADR defines the Security agent behavior.

## Decision

### Agent Profile

| Field | Value |
|-------|-------|
| ID | `agent.security` |
| Version | `v1` |
| Kind | `Agentic` |
| Event Subscription | `vulnerability.detected.v1` |
| Lens | `VulnerabilityImpactLens` |

### Prompt Design (R-1 Mitigation)

The prompt template is a **compile-time constant**. Dynamic data from the lens (blast radius results) is injected as structured JSON.

```
You are the GOLEM Security Agent.
[Static instructions...]
Input Data (from graph lens):
{structured JSON lens result}
```

### Lens Spec

```go
VulnerabilityImpactLens(roots=[purl], depth=5, maxNodes=500, maxEdges=1000)
```

Traversal: Component → CONTAINS⁻¹ → SBOM → HAS_SBOM⁻¹ → Artifact → RELEASED_AS → Release, plus vulnerability edges (AFFECTED_BY, MITIGATED_BY).

### LLM Reasoning

The LLM evaluates:
1. **Vulnerability impact**: Which releases are affected by this CVE?
2. **Fix status**: Is the vulnerability remediated in the target release version?
3. **VEX appropriateness**: Should a VEX "fixed" statement be issued?

### VEX Output Shape

```json
{
  "operations": [
    {
      "type": "CreateNode",
      "kind": "VEXStatement",
      "payload": {
        "cve_id": "CVE-YYYY-XXXXX",
        "state": "fixed",
        "justification": "Version X.Y.Z includes security patch"
      }
    },
    {
      "type": "AddEdge",
      "kind": "MITIGATED_BY",
      "from": "<artifact-id>",
      "to": "<vex-statement-id>"
    }
  ]
}
```

### Held-Out Fixture

```
internal/agent/harness/fixtures/cases/v1-security/sbom-with-cve.json
internal/agent/harness/fixtures/cases/v1-held-out-security/sbom-with-unknown-cve.json
```

The held-out fixture tests unknown CVE handling: when the CVE is not in the graph, the agent should output no operations.

## Consequences

### Positive
- Automated VEX proposal reduces manual security analysis
- Lens-based blast radius is deterministic and complete
- Static prompt template mitigates prompt injection

### Negative
- LLM may propose incorrect VEX statements
- Human approval required before applying VEX (per REQ-017)

### Risks & Mitigations
- **Prompt injection**: Static template + Redactor (ADR-066)
- **Incorrect VEX**: Human approval gate on proposal apply
- **False positives**: Policy evaluator can block proposals
