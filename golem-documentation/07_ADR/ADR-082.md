# ADR-082: OIDC JWT Authentication Port

**Status**: Accepted

**Date**: 2026-08-18

## Context

M8 (GA release) requires agent-to-agent and human-to-agent authentication using
OIDC-compatible JWT tokens (REQ-OIDC-001 through REQ-OIDC-005). This ADR describes
the OIDC verification adapter that validates JWTs against a JWKS endpoint and
emits audit events for every verification attempt.

## Decision

We will implement OIDC JWT verification with the following characteristics:

### 1. OIDC Adapter (`adapters/authn/oidc/`)

```go
// Config configures the OIDC adapter.
type Config struct {
    IssuerURL string        // e.g. "https://auth.example.com/realms/golem"
    ClientID  string        // OAuth 2.0 client ID
    CacheTTL  time.Duration // JWKS cache TTL (default 1h)
}

// Adapter implements ports.AuthN using OIDC JWT verification.
type Adapter struct { ... }

// NewAdapter creates an OIDC adapter with the given configuration.
func NewAdapter(config Config) *Adapter
```

### 2. JWKS Caching

- JWKS is fetched from `{IssuerURL}/.well-known/jwks.json`
- Cached with configurable TTL (default 1h)
- Thread-safe cache with RWMutex refresh
- Falls back to stale cache on JWKS fetch failure (availability over freshness)

### 3. JWT Verification

Claims verified:
- `iss` (issuer) matches `IssuerURL`
- `aud` (audience) matches `ClientID`
- `exp` (expiration) is not in the past
- `nbf` (not before) is not in the future
- `kid` (key ID) matches a key in the current JWKS

Signature algorithms supported: RS256, RS384, RS512 (RSA PKCS1v15).

### 4. Audit Events (REQ-OIDC-004)

```go
EventOIDCTokenVerified = "oidc.token.verified.v1"
EventOIDCTokenRejected = "oidc.token.rejected.v1"

type OIDCTokenVerifiedPayload struct {
    Subject     string   `json:"subject"`
    Issuer      string   `json:"issuer"`
    Groups      []string `json:"groups,omitempty"`
    Correlation string   `json:"correlation_id,omitempty"`
}

type OIDCTokenRejectedPayload struct {
    Error       string `json:"error"`        // error message
    Issuer      string `json:"issuer,omitempty"`
    Correlation string `json:"correlation_id,omitempty"`
}
```

Every verification attempt emits either `oidc.token.verified.v1` (success) or
`oidc.token.rejected.v1` (failure). This provides a complete audit trail for
security investigations.

### 5. Error Handling

```go
var (
    ErrAuthFailed   = errors.New("authn: verification failed")
    ErrTokenExpired = errors.New("authn: token expired")
    ErrKeyNotFound  = errors.New("authn: signing key not found in JWKS")
)
```

## Consequences

- **Positive**: Standard OIDC compatibility for enterprise identity providers.
- **Positive**: JWKS caching reduces latency and provider load.
- **Positive**: Complete audit trail via verification events.
- **Negative**: JWKS endpoint must be available at startup.
- **Negative**: Token expiry check adds verification latency.
