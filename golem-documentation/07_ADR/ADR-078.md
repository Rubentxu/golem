# ADR-078: Usage Metering

**Status**: Accepted

**Date**: 2026-08-18

## Context

M8 introduces usage metering to track resource consumption per tenant. This ADR describes
the metering model and data pipeline.

## Decision

We will implement usage metering with the following characteristics:

1. **Metering Model**:
   - Per-tenant usage counters for events, storage, compute time
   - Metering events emitted on each operation
   - Hourly rollup for reporting

2. **Metering Events**:
   - `metering.event.count`: Increment event counter
   - `metering.storage.append`: Add to storage counter
   - `metering.compute.time`: Add to compute time counter

3. **Metering Pipeline**:
   - Events flow through the journal
   - Meter aggregator consumes journal events
   - Hourly rollup job computes aggregated metrics
   - Metrics stored in time-series format

4. **S3 Sink**: Daily rollups exported to S3 for long-term storage.

5. **DLQ**: Failed metering events are sent to a dead-letter queue for retry.

## Consequences

- **Positive**: Accurate per-tenant billing.
- **Positive**: Time-series data enables trend analysis.
- **Negative**: Metering adds overhead to every operation.
- **Negative**: S3 export requires bucket configuration.
