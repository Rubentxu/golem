# ADR-078: Audit Export

**Status**: Accepted

**Date**: 2026-08-18

## Context

M8 (GA release) requires a tamper-evident, independently verifiable audit trail
for compliance (REQ-AUDIT-001 through REQ-AUDIT-005). The canonical export
archive must be cryptographically signed so that auditors can verify integrity
without access to the live system.

## Decision

We will implement the audit export system with the following characteristics:

### 1. Canonical Export Format (v2)

Exports are produced as tar archives with the following structure:

```
manifest.json          # v2 manifest with SignedBlock
nodes.jsonl           # newline-delimited JSON nodes
edges.jsonl           # newline-delimited JSON edges
journal-position.json  # journal head at export time
ontology.schema.json   # schema version snapshot
```

Manifest v2 format (REQ-CANON-MOD-001):

```go
type Manifest struct {
    FormatVersion   string            `json:"format_version"`   // "2"
    TenantID        string            `json:"tenant_id"`
    CreatedAt       string            `json:"created_at"`       // RFC3339
    JournalPosition JournalPosition   `json:"journal_position"`
    Files           map[string]FileDigest `json:"files"`       // path → sha256
    Counts          Counts            `json:"counts"`
    SignedBlock    *SignedBlock     `json:"signed_block,omitempty"`
}

type SignedBlock struct {
    KeyID     string   `json:"key_id"`      // e.g. alias/golem-export
    Signature string   `json:"signature"`   // hex RSASSA-PKCS1-v1.5-SHA-256
    Regions   []string `json:"regions,omitempty"` // S3 replication regions
}
```

### 2. KMS Signing (AC-14, REQ-AUDIT-002)

- Algorithm: `RSASSA_PKCS1_V15_SHA_256` (AWS SDK v2 `SigningAlgorithmSpec`)
- Key: resolves `alias/golem-export` via `DescribeKey` at signing time
- What is signed: the canonical JSON bytes of the manifest excluding `SignedBlock`
- Signature is stored in `SignedBlock.Signature`

### 3. S3 Multi-Region Upload (REQ-AUDIT-003)

- Multipart upload with 5MB minimum part size
- Exponential backoff retry: 3s, 6s, 12s (3 retries)
- SSE-KMS encryption with the export CMK
- Replication to secondary region for durability

### 4. Export Cron (REQ-AUDIT-005)

- Daily at 02:00 UTC (`GOLEM_EXPORT_CRON` env var)
- Controlled by `GOLEM_EXPORT_ENABLED=true` env var
- Pipeline: `Exporter.Export` → S3 upload → KMS sign → emit `audit.export.completed.v1`

### 5. Audit Event (REQ-AUDIT-005)

```go
EventAuditExportCompleted = "audit.export.completed.v1"

type AuditExportCompletedPayload struct {
    TenantID      string   `json:"tenant_id"`
    JournalHead   uint64   `json:"journal_head"`
    NodeCount     uint64   `json:"node_count"`
    EdgeCount     uint64   `json:"edge_count"`
    S3Bucket     string   `json:"s3_bucket"`
    S3Key        string   `json:"s3_key"`
    KMSKeyAlias  string   `json:"kms_key_alias"`
    Signature     string   `json:"signature"`
    FormatVersion string   `json:"format_version"`
    Regions      []string `json:"regions,omitempty"`
    DurationMs   int64    `json:"duration_ms"`
}
```

### 6. Canonical Importer (REQ-AUDIT-004)

Replay a canonical export tar into an empty journal. Verification modes:

- `DryRun`: validates archive without writing
- `VerifySignature: true`: rejects v2 manifests with invalid KMS signature

## Consequences

- **Positive**: Tamper-evident audit trail for compliance auditors.
- **Positive**: Cryptographic non-repudiation via KMS signatures.
- **Positive**: Multi-region S3 provides durable offsite backup.
- **Negative**: S3 and KMS configuration adds deployment complexity.
- **Negative**: Signature verification adds import latency.
